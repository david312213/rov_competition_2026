## 1. 当前已经可运行的内容

当前 GitHub 代码适配后的测试目标是先安全跑通“无机械爪群体搜索—接近”，而不是直接实艇盲抓：

```text
原始 GitHub 流程
搜索 → 识别目标群 → 接近 → 盲抓下降 → 机械爪抓取 → 继续搜索

当前测试流程
搜索 → 识别目标群 → 接近 → 全零停车并结束
```

已完成的适配如下：

1. 新 YOLO 模型类别为 `echinus`、`holothurian`、`scallop`、`snail`。群体流程不再依赖原代码中的 `starfish`；当前使用 `scallop`（扇贝）和 `snail`（海螺），两类当前阈值均为 `0.18`。
2. `start_cluster_collection_test.sh` 运行无机械爪测试模式：搜索、识别、群体选择、对准、接近，然后停车。它不应进入盲抓下降或机械爪动作。
3. 已跑通 GPU、Pygame、YOLO 模型加载和无机械爪测试程序的关键前置链路。

当前明确**没有**改动或验证的内容：模型权重、飞控 IP、UDP 端口定义、真实推进器权限、ROS 解锁权限、机械爪硬件配置、正式盲抓流程的机械爪安全门、真实盲抓下降、机械爪开合、抓取成功率、抓取后继续搜索。

## 2. 运行前置条件

```text
QGC MAVLink：14550
自主代码 MAVLink：14551
QGC 视频：5600
软件视频输入：5700
```

`14551` 必须由 MAVProxy/BlueOS 等额外转发给自主代码。QGC 能手动控制，并不等于自主程序能收到飞控心跳。

进入搜索—接近测试前，QGC 应处于 `Depth Hold`；它对应代码要求的 `ALT_HOLD`。飞行模式不符合时，程序应拒绝开始自主运动。

## 3. 今晚确定的后续搜寻策略

这是**独立于群体盲抓和机械爪流程**的单目标扇贝搜寻策略。它尚未接入实艇运行入口，不能替代上一节的群体搜索—接近测试。

### 搜寻路径

比赛区域按“右侧为墙、半圆区域向左展开、机器人从右下角入水”理解：

```text
第 1 带：沿墙向上持续前进搜寻
按 N：向半圆内部横移一小段 → 原地约 180° 翻转
第 2 带：向下持续前进搜寻
按 N：继续向半圆内部横移一小段 → 原地约 180° 翻转
第 3 带：向上持续前进搜寻
```

所有搜寻带均持续前进，**不使用预设前进时长、总带数或自动换带**。何时换带由操作员短按 `N` 决定。向上行进时向左横移；掉头后向下行进时向右横移，才能在地理方向上持续向半圆内部展开。

### 搜寻按键约定

| 按键 | 仅搜寻策略中的行为 |
|---|---|
| `T` | 停止当前运动 → 触底确认 → 上浮到观察高度 → 恢复当前搜寻方向。 |
| `P` | 立即四轴归零并暂停搜寻；再次按 `P` 恢复。若在定高过程中暂停，应先按 `T` 重新定高。 |
| `A` / `D` | 按已标定的短时偏航进行左/右纠偏，再继续前进。 |
| `N` | 停止前进 → 向半圆内部横移固定距离 → 原地按实测时长翻转约 180° → 继续前进。 |
| `0` | 终止搜寻，取消所有路径状态，仅持续发送上浮指令；水面由 QGC 或停止程序接管。 |

扇贝连续稳定识别后，搜寻策略应全零停车并等待独立抓取策略交接。识别丢失不等于目标不存在；未来抓取策略将由人工短按授权进入下潜抓取，但不属于本次搜寻交付。

## 4. 最小实测任务

不需要测每条带的前进时间，也不需要测半圆尺寸。只需把下表动作分别在低推力、空旷水域中验证并记录。

| 编号 | 需要记录的内容 | 验收标准 |
|---|---|---|
| M1 | 前进推力与方向 | 持续前进方向正确，画面与实际艇体方向一致。 |
| M2 | 左、右横移各自的推力和持续时间 | 一次 `N` 横移距离较小，且不会明显偏航。 |
| M3 | 左、右约 180° 翻转的推力和持续时间 | 实际翻转效果接近预期；左右数据分开记录。 |
| M4 | `A/D` 左右纠偏的推力和持续时间 | 单次纠偏较小，完成后能继续原方向前进。 |
| M5 | `T` 的下潜/上浮方向、触底判定与观察高度 | 能触底后上浮；误判或超时必须停车，不得继续前进。 |
| M6 | `0` 的上浮方向与推力 | 能覆盖任意搜寻状态；前进、横移、偏航均为零。 |
| M7 | `scallop` 类别名、停车置信度和连续不同帧命中数 | 稳定目标会停车；同一帧重复处理不得重复计数。 |

每条记录附：日期、操作者、电池状态、是否有明显水流、推力值、持续时间、实际效果、是否通过。不要把未测得的数值填入配置。

## 5. 接下来需要补齐的结果

以下不是分工，而是软件继续落地前必须拿到的实测结论。每项只要给出简短记录或视频即可。

| 需要完成什么 | 需要交给软件的结果 | 软件据此做什么 |
|---|---|---|
| 验证前进 | 一个确认方向正确、画面与艇体方向一致的前进推力。无需测前进总时长。 | 搜寻状态持续使用该前进推力；何时换带由人工按 `N` 决定。 |
| 测一次左、右横移 | 左横移与右横移各自的推力、持续时间，以及实际横移效果。 | 写入 `N` 的“向半圆内部横移一小段”动作。 |
| 测一次左、右大转向 | 左、右各自接近 180° 的偏航推力与持续时间。 | 写入 `N` 换带后的翻转动作；不依赖罗盘认为自己转了多少度。 |
| 测一次小纠偏 | `A`、`D` 各自的偏航推力和持续时间。 | 写入短按纠偏动作，结束后恢复持续前进。 |
| 验证触底定高 | 下潜/上浮方向是否正确；触底后是否能上浮到合适观察高度；是否出现误判。 | 确定 `T` 能否在海底坡面上作为重新定高动作；失败时保持停车。 |
| 验证比赛结束上浮 | `0` 的上浮方向和合适推力。 | 保证 `0` 覆盖全部搜索状态，只上浮、不再恢复任务。 |
| 检查扇贝识别 | 确认类别名为 `scallop`；给出先用于停车提示的置信度和连续不同帧数；记录典型漏检画面。 | 写入“稳定识别后停车”的条件；后续抓取不以当前识别是否仍存在作为唯一前提。 |
| 检查现场软件链路 | QGC 处于 `Depth Hold`；`14550/14551/5600/5700` 均已连通；按键窗口能收到 `T/P/A/D/N/0`。 | 允许启动无机械爪测试，避免现场因心跳、视频或按键焦点问题中止。 |

拿到上述结果后，下一步是把参数写入搜寻配置，并按如下顺序验证：

```text
先验证 T / P / 0
→ 验证持续前进与 A/D
→ 验证一次 N 横移 + 翻转
→ 验证稳定识别停车
→ 最后才把独立抓取策略接入
```

## 6. 提交与现场原则

1. 提交代码前先保留本说明、修改记录和测试日志；不提交现场网络地址、口令、视频原始大文件或未确认的实艇配置。
2. 先运行无机械爪群体搜索—接近测试，确认飞控、视频和模式检查；不能因“能手动操控”就跳过 14551 心跳验证。
3. `0` 是比赛结束上浮，不是一般暂停。出现方向、高度或画面异常时优先 `P`，由操作员观察后选择恢复、`T` 重定高或 `0` 终止。
4. 单目标搜寻与抓取必须保持两个独立状态机；搜寻代码不得直接发送机械爪命令。
