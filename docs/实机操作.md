# 实机操作：从只读到自主

## 0. 人员和机械条件

- ROV 必须在水中，不能让水下推进器长时间干转。
- 机械固定方式不能阻碍紧急断电，线缆不能进入桨叶。
- 一人负责电脑和命令；另一人只负责观察危险区、急停和断电。
- 每发一个命令前，操作员口述“预期哪个方向动、什么条件立即停”。
- QGC 保持遥测和人工上锁能力，但 ROS 测试时关闭手柄输出。

## 2. 创建实艇配置

只做一次复制，之后只编辑根目录这一份：

```bash
cp ros2_ws/src/rov_competition/config/robot.example.yaml config/robot.yaml
```

先保持：

```yaml
  allowed_flight_modes: ["MANUAL"]

  allow_live_actuation: false
  allow_ros_arming: false
  allow_gripper_actuation: false
```

根据 QGC 参数备份和实物确认 `expected_frame_config`、Motor1–Motor8、方向、failsafe、机械爪绝对输出口和深度换算。旧六推进器日志不能直接导入。

## 3. 只读网关与预检

终端 A：

```bash
ros2 launch rov_competition telemetry.launch.py \
  robot_config:="$PWD/config/robot.yaml"
```

预期日志包含 MAVLink 已连接、真实输出 `DISABLED`。保持这个终端运行，不要在同一个终端输入下一条命令。

终端 B：

```bash
ros2 topic echo /rov/telemetry
```

```bash
ros2 topic echo /rov/control/status
```

确认数据来自真实飞控，深度、航向、模式、解锁状态会随实物变化。`Ctrl+C` 只结束当前 `echo`，不会关闭终端 A。

## 4. 打开点动所需的三道门

先停止终端 A 的网关并确认飞控上锁。编辑 `config/robot.yaml`：

```yaml
control:
  profile: "commissioning"
  allowed_flight_modes: ["MANUAL"]
  expected_frame_config: 2  # 这里只是格式示例，必须以实艇为准

safety:
  allow_live_actuation: true
  allow_ros_arming: true
  allow_gripper_actuation: false
```

重新启动网关：

```bash
ros2 launch rov_competition telemetry.launch.py \
  robot_config:="$PWD/config/robot.yaml" \
  enable_actuation:=true \
  enable_ros_arming:=true
```

网关会运行只读预检。任何关键项失败都不继续。

终端 B 开启运行时许可：

```bash
ros2 service call /rov/control/set_enabled std_srvs/srv/SetBool "{data: true}"
```

在 ROV 固定、危险区清空、飞控为 `MANUAL` 后，正常解锁：

```bash
ros2 service call /rov/control/set_armed rov_interfaces/srv/SetArmed \
  "{arm: true, confirmation: 'ARM ROV'}"
```

不要使用 `21196` 强制解锁。预解锁检查失败就解决原因。

### 5.1 临时打断推进器电调的待机蜂鸣

如果已经确认声音来自推进器电调的待机蜂鸣，而不是漏水、电池、温度或
飞控报警，可以人工执行一次固定的低功率点动：

```bash
./scripts/nudge_thrusters_once.sh forward
```

环境安装、ROS 编译和 `robot.yaml` 实艇配置完成后，不需要另外开三个终端。
脚本会自行加载环境，监听 BlueOS 的 `14551` MAVLink，启动网关并预检，
开启本次运行许可，正常解锁，固定发送 `0.05 / 1.0s`，最后连续回中、
上锁、关闭许可并退出自己启动的网关。可选方向只有 `forward、backward、
left、right、up、down`。它不会后台循环，也不会绕过网关预检。

BlueOS 向岸上电脑 `14551` 发送 MAVLink，以及 `robot.yaml` 允许真实输出和
ROS 解锁，是一次性配置，脚本不能替代艇载端的数据源。每次运行仍要求
输入 `NUDGE ROV ONCE`，而且飞控必须在执行前处于上锁状态。

这不是“完全无影响”的命令：参与该动作的推进器会真的转，艇体也可能
移动。单一方向通常只会带动部分推进器，因此不能保证所有电调都停止叫；
而且经过电调配置的待机时间后，蜂鸣还会回来。必须在 ROV 完全浸没、
可靠固定、危险区无人、QGC 可上锁且安全员可断电时使用。长期解决办法是
核对具体电调型号后调整其 Beacon/待机蜂鸣配置，而不是让脚本无人值守地
周期转动推进器。

## 6. 转向闭环

固定顺序：右转 `30° → 90° → 180° → 360°`。每一级通过方向、停止、上锁和跨零检查后才进下一级。

```bash
ros2 run rov_competition rov_turn_test \
  --direction right --angle 30 --value 0.05 \
  --config "$PWD/config/robot.yaml"
```

```bash
ros2 run rov_competition rov_turn_test \
  --direction right --angle 30 --value 0.05 \
  --config "$PWD/config/robot.yaml" \
  --execute --confirm "TURN ROV"
```

工具使用真实航向累计角度。航向跳变、实际方向相反、长期无进展、遥测过期、总超时或 `Ctrl+C` 都停止并上锁。

## 7. QGC 默认视频与软件副流

BlueOS 对同一个 H.264 摄像头配置两路 UDP 输出：

```text
BlueOS ──→ 5600 ──→ QGC 默认视频
       └─→ 5700 ──→ 岸上软件分流器 ──→ 5702 YOLO
                                      └─→ 5704 原始录像
```

两路都从艇载端发出；QGC 不再充当转发器。岸上软件分流器只复制 `5700`
收到的原始 RTP 包，不解码、不重新编码。QGC 使用默认 `5600`，并开启
`Low Latency Mode`。设置方法见 [QGC Video 设置](https://docs.qgroundcontrol.com/master/en/qgc-user-guide/settings_view/video.html)。

### 7.1 一键只读视频测试

```bash
cd /home/persica/rov_competition_2026
./scripts/start_video_test.sh
```

脚本检查 QGC 是否已经监听 `5600`，再启动 `5700 → 5702` 软件副流和
YOLO。它不会启动飞控网关、不会解锁，也不会驱动机器人。带框查看器中
选择 `/rov/annotated_image`，传输方式选择 `compressed`。按 `Ctrl+C`
停止软件副流和 YOLO，QGC 的 `5600` 画面不受影响。

如果不想自动打开窗口：

```bash
./scripts/start_video_test.sh --no-qgc
./scripts/start_video_test.sh --no-viewer
```

### 7.2 手动排错

终端 A 复制软件副流：

```bash
ros2 run rov_competition rov_stream_bridge \
  --source-port 5700 \
  --no-qgc \
  --inference-host 127.0.0.1 --inference-port 5702 \
  --no-display
```

端口检查：

```bash
ss -lunp | grep -E ':(5600|5700|5702|5704)\b'
```

QGC 应监听 `5600`，分流器监听 `5700`，YOLO 启动后监听 `5702`；录像
模式下录像器监听 `5704`。如果 QGC 和 YOLO 同时花屏，先检查 BlueOS
摄像头、全长水密缆和原始丢包；只有 YOLO 异常时再检查 `5700/5702`
本机链路。关闭任一软件分支不应影响另一分支。

GPU 必须显示 `.venv` 中的 CUDA 版 PyTorch：

```bash
python - <<'PY'
import torch
print(torch.__version__)
print(torch.__file__)
print(torch.cuda.is_available())
print(torch.cuda.get_device_name(0) if torch.cuda.is_available() else "NO CUDA")
PY
```

查看感知输出：

```bash
ros2 topic hz /rov/detections
ros2 topic hz /rov/annotated_image/compressed
ros2 run rqt_image_view rqt_image_view
```

用手机秒表同时出现在真实场景、QGC 和带框画面里，测量端到端延迟。
YOLO 相对 QGC 的额外延迟目标不超过 `100 ms`。

## 8. 键盘驾驶并拍摄数据集

这一步只用于人工驾驶拍摄新训练数据。它不启动 YOLO、不读取
权重、不控制机械爪，也不会“一启动就自动沉底”。下潜必须由操作员
按住向下方向键完成。日常操作请直接按
[键盘采集 README](键盘采集README.md) 执行；本节保留工程背景和参数解释。

### 8.1 一次配置

确认 `config/robot.yaml` 使用已经通过实艇点动的值：

```yaml
mavlink:
  connection_uri: "udpin:0.0.0.0:14551"

control:
  profile: "commissioning"
  allowed_flight_modes: ["ALT_HOLD"]
  command_limit: 0.80

safety:
  allow_live_actuation: true
  allow_ros_arming: true
  allow_gripper_actuation: false
```

复制数据集配置：

```bash
cp ros2_ws/src/rov_competition/config/dataset.example.yaml config/dataset.yaml
```

`config/dataset.yaml` 不再包含软件深度限制，只需核对键盘幅值：

```yaml
manual_control:
  initial_command: 0.20
  maximum_command: 0.80
```

深度只用于显示、日志和可选回收，不参与启动或驾驶门控。
姿态消息允许最多 `3.0 s` 的短时中断；飞控心跳、模式和控制状态仍按
各自阈值检查。控制状态允许 `2.0 s`，同时每帧清理积压的 ROS 回调。

### 8.2 QGC 与 BlueOS 端口

BlueOS 直接向岸上发送四路数据：

```text
MAVLink：14550 给 QGC，14551 给 ROS 飞控网关
视频：   5600 给 QGC，5700 给软件分流器
```

QGC 开启 UDP 自动连接并使用默认 `5600` 视频；软件副流再在本机复制到
录像器 `5704`。QGC 必须保留人工上锁能力。BlueOS 的 Endpoint 和摄像头
输出只需配置一次，保存后不再每天修改 QGC 端口。

### 8.3 一键启动

安装、编译完成后，一个终端执行：

```bash
cd /home/persica/rov_competition_2026
./scripts/start_dataset_collection.sh
```

脚本依次检查环境和端口，启动飞控网关和软件视频分流，
然后开始 MKV 录像。它必须真正观察到录像文件增长，并确认
`ALT_HOLD`、真实深度、只读预检、ROV 已上锁和机械爪权限已关闭，
才显示最后现场确认词。

### 8.4 按键

| 按键 | 动作 |
|---|---|
| `W / S` | 前进 / 后退 |
| `A / D` | 左移 / 右移 |
| `1 / 2` | 左转 / 右转 |
| `↑ / ↓` | 上升 / 下潜 |
| `+ / -` | 每次增加 / 减少 `0.05` |
| `Space` | 四轴立即回中，ALT_HOLD 保持当前深度 |
| `0` | 正常停录像；深度可用则回收，否则直接上锁 |
| `Esc` / 关窗口 / `Ctrl+C` | 立即回中、锁存急停、上锁 |

默认幅值为 `0.20`，最高 `0.80`。只有按住才会运动；松开、
窗口失去焦点或按空格都会回中。可以按多个方向，每个轴保留设定的
指令强度；八推进器混控和最终输出饱和由 ArduSub 负责，每个轴仍受
网关 `0.80` 限幅。`0.80` 只是可调上限，必须从 `0.20` 逐级增加。

键盘采集不设置绝对或相对深度上限，也不会根据深度拦截向下指令。
深度可用时仍会显示和记录。

### 8.5 结束、故障和文件

正常结束必须按 `0`，顺序是：

```text
四轴回中 → 给录像器 EOS 并验证 MKV → 可选回启动深度 → 上锁
```

如果当前已比启动深度浅，工具不会为了追目标而重新下潜。若没有有效
深度，程序跳过自动回收并直接上锁。MAVLink、心跳、控制状态或模式
异常仍会急停上锁。

每次文件位于：

```text
output/datasets/YYYYMMDD_HHMMSS/
├── video_raw.mkv
├── events.csv
├── session.json
└── logs/
```

异常断电或封装失败时会保留 `video_raw.partial.mkv`，不会伪装成完整录像。
后续按每秒 5 帧抽图：

```bash
cd output/datasets/YYYYMMDD_HHMMSS
mkdir -p frames
ffmpeg -i video_raw.mkv -vf "fps=5" -q:v 2 frames/%06d.jpg
```

先人工删掉模糊、重复和无效帧，再标注。不要把连续视频每一帧都当成
独立样本，否则训练/验证集很容易泄漏几乎相同的画面。

### 8.6 有手柄时：只录像

已经能用 QGC 和手柄驾驶时，不要再启动键盘控制。完整步骤见
[手柄采集 README](手柄采集README.md)。日常只需运行：

```bash
cd /home/persica/rov_competition_2026
./scripts/start_dataset_recording.sh
```

脚本会自动尝试打开 QGC；QGC 保持默认 `5600` 视频。
这个入口不读取 `robot.yaml`，不启动飞控网关、YOLO、
键盘驾驶或机械爪，也不占用 MAVLink 端口。QGC 和手柄的
原有 MAVLink 连接保持不变。

命令运行后会立即开始录制。采集完成后，先松开手柄并确认
ROV 停稳，再回到终端按 Enter。`Ctrl+C` 也会正常发送 EOS 并
封装 MKV，但它只停录像，不会替你停止、上锁或上浮 ROV。

输出目录为：

```text
output/datasets/YYYYMMDD_HHMMSS/
├── video_raw.mkv
├── session.json
└── logs/
```

`session.json` 会明确记录“本程序没有观察 QGC 手柄控制量”，不会把
未记录的飞控数据伪装成完整标注。

## 9. 机械爪标定与自主档案

### 9.1 机械爪必须先单独验收

两份旧工程的共同点是都发送 `MAV_CMD_DO_SET_SERVO`，差别在“用了几个
输出、输出号和 PWM 值”。照片只能看清机械结构，看不见信号线最终接入
Pixhawk 的位置，因此不能靠照片判断是哪一版。当前代码保留两个候选档案：

| 档案 | 历史接法 | 开爪 | 闭爪 |
|---|---|---|---|
| `dalian` | 单路 S12/AUX4 | 1775、1800、…、1900 | 1900、1875、…、1625 |
| `rst` | 左 S11/AUX3；右 S10/AUX2 | 左 950；右 1050 | 左 1450；右 500 |

`dalian` 来自旧大连工程 `move/gripper.py`；`rst` 来自 RST 打包工程中命名最明确的
`open_claw/close_claw` 实现。RST 工程的其他实验脚本还有互相冲突的数值，所以
这里的 `rst` 也只是候选，不是已经证明适配本艇的结论。特别是 `500us` 远低于
常见舵机脉宽，接错驱动器可能让机构撞限位或持续堵转。

网关只加载 `active_profile` 指定的一份档案，运行中不允许切换。大连的多步渐变
由非阻塞定时器发送；RST 的左右两路在同一节拍背靠背发送。期间遥测、看门狗和
急停仍会运行，新动作不能覆盖尚未完成的旧动作。

第一次验收前：

1. 从物理上断开八个推进器的动力或信号，但保留飞控和机械爪所需的正确供电。
2. 让机械爪悬空、无负载，手、线缆和工具全部离开夹持区，安全员只负责断电。
3. 顺着机械爪信号线核对真实输出。若只接 S12，优先试 `dalian`；若明确有两路接到 S10/S11，才考虑 `rst`。
4. 每个候选输出的 `SERVOx_FUNCTION` 必须是 `0`、`1`、`22`、`23`、`28` 或 `51..66`，并且不能与 Motor1–Motor8 重合。`rov_preflight` 会逐个列出。
5. Pixhawk1 上 S10/S11/S12 分别是 AUX2/AUX3/AUX4；因此 `dalian` 要求 `BRD_PWM_COUNT >= 4`，`rst` 要求 `BRD_PWM_COUNT >= 3`。

两个候选档案已经完整写在模板中。不要先改 `active_profile`、不要启动正常
飞控网关，也不要解锁。候选测试会读取 `robot.yaml`，生成一个临时安全副本，
在副本中选择档案并强制关闭真实运动、ROS 解锁和正常机械爪权限；原文件不会
被修改。如果现场 `robot.yaml` 还是只含 `output_channel/open_pwm/close_pwm`
的旧格式，工具会仅在这份临时副本中补全两套候选档案；不会将
旧数值当成已标定结论，也不会覆盖实艇配置。

第一次固定使用这个顺序：

```bash
cd /home/persica/rov_competition_2026

# 1. 推进器已物理断开、飞控上锁后，先试单路 S12
./scripts/start_gripper_test.sh dalian

# 2. 上锁、断电、重新核对接线和执行器规格后，才可试双路 S10/S11
./scripts/start_gripper_test.sh rst
```

工具会先运行只读预检，确认候选输出没有被 Motor1–Motor8 或其他功能占用、
AUX PWM 已启用且飞控仍然上锁。每一步都等待匹配的
`MAV_CMD_DO_SET_SERVO` ACK，并在发送下一步前再次检查心跳和上锁状态。
它不会写飞控参数、不会启动网关、不会解锁，也不会自动设置 `calibrated`。

`dalian` 使用普通确认词；`rst` 因历史值包含 `500us`，还会要求第二确认词。
没有核对双路接线、驱动器规格和机械行程时，不得输入第二确认词。两套档案之间
必须上锁、断电并重新检查接线，不能连续“碰碰运气”。

每次测试保存到：

```text
output/gripper_tests/YYYYMMDD_HHMMSS_dalian/
├── commands.csv
├── result.json
├── resolved_gripper_test.yaml
└── preflight/
```

记录包含档案名、绝对输出号、每步 PWM、ACK、操作员确认的实际开合和备注。
ACK 只证明飞控接受了命令；如果输出数值改变但爪子不动，应查供电、共地、
信号线、真实输出口和执行器，不应继续扩大 PWM。有卡死、异响、过热或方向
相反时立即断电。

只有某个档案的开爪和闭爪都由操作员确认成功，才人工修改正式
`config/robot.yaml`：

```yaml
gripper:
  active_profile: "dalian"  # 或经实测通过的 rst
  profiles:
    dalian:
      calibrated: true

safety:
  allow_gripper_actuation: true
```

若通过的是 `rst`，在确认扩展值确实符合硬件规格后，还必须显式设置
`profiles.rst.allow_extended_pwm: true`。未通过时所有 `calibrated`、
`allow_extended_pwm` 和 `allow_gripper_actuation` 保持 `false`。

### 9.2 切换到自主档案

只有单轴、转向、断链、视频和参数标定全部通过后：

1. 停止网关并确认上锁。
2. 将 `robot.yaml` 改为 `control.profile: "autonomy"`。
3. 将允许模式改为 `allowed_flight_modes: ["ALT_HOLD"]`。
4. 只有第 9.1 节确认正确 `active_profile` 并完成实物验收，才能保持 `allow_gripper_actuation: true` 和该档案的 `calibrated: true`。
5. 按本文第 11 节完成 `autonomy.yaml` 的所有标定和记录。

保持第 7 节的分流器运行。另一个终端启动网关、感知和自主节点：

```bash
ros2 launch rov_competition competition.launch.py \
  robot_config:="$PWD/config/robot.yaml" \
  autonomy_config:="$PWD/ros2_ws/src/rov_competition/config/autonomy.yaml" \
  targets_config:="$PWD/ros2_ws/src/rov_competition/config/targets.yaml" \
  video_source:=5702 \
  gstreamer:=true \
  udp_mpegts:=false \
  display_window:=false \
  enable_actuation:=true \
  enable_ros_arming:=true
```

终端 B 观察：

```bash
ros2 topic echo /rov/mission/status
```

确认 QGC 已设为 `ALT_HOLD`，ROV 已完全浸没，依次调用运行时许可和正常解锁，然后开始任务：

```bash
ros2 service call /rov/control/set_enabled std_srvs/srv/SetBool "{data: true}"
```

```bash
ros2 service call /rov/control/set_armed rov_interfaces/srv/SetArmed \
  "{arm: true, confirmation: 'ARM ROV'}"
```

```bash
ros2 service call /rov/mission/start std_srvs/srv/Trigger "{}"
```

若返回失败，完整保存并阅读缺项列表。不要通过改代码删除门控。

人工中止：

```bash
ros2 service call /rov/mission/abort std_srvs/srv/Trigger "{}"
```

独立网关急停：

```bash
ros2 service call /rov/control/emergency_stop std_srvs/srv/Trigger "{}"
```

## 10. 必测故障

在固定和低功率条件下分别验证：

- 自主节点 `Ctrl+C`；
- 命令发布者进程崩溃；
- 摄像头断流；
- MAVLink 链路断开；
- 模式从 `ALT_HOLD` 变化；
- 深度或航向消息停止更新；
- 机械爪服务拒绝；
- 人工任务中止和网关急停。

每一种都必须保存终端完整日志、QGC 状态和录像。无法确认推进器停止并上锁时，不调试软件，先物理断电。

## 11. 自主参数标定

只从 `ros2_ws/src/rov_competition/config/autonomy.yaml` 最前面的 `field_tuning` 开始改。每次记录日期、电池、负载、水况、改前值、改后值、录像和结论；一次只改一类参数。

### 11.1 相对下潜

默认：

```yaml
descent_delta_m: 0.30
descent_tolerance_m: 0.05
```

ROV 实际下沉时，`/rov/telemetry.depth_m` 必须增加。先用已知水深检查零点和单位；数据反向或比例不对时，修正 `robot.yaml` 的深度换算，不要用状态机增益抵消传感器错误。

先确认能稳定进入容差，再调 `descent_gain`；不要一开始就提高 `descent_max_command`。

### 11.2 无 DVL 的前进距离

`0.40 m` 只能通过实测平均速度换算时间：

1. 固定使用 `advance_forward_command: 0.05`。
2. 在池边布置可测量的起点和终点。
3. 每次只运行短时间，至少重复 5 次。
4. 用人工测得的距离和时间计算速度。
5. 剔除碰撞、缆绳拉扯和明显流场干扰样例。
6. 用保守代表值填写 `advance_estimated_speed_mps`。

例如实测为 `0.20 m/s`，状态机会自动得到 `0.40 / 0.20 = 2.00 s`。电量、挂载、缆绳或水流变化后必须重测。

### 11.3 图像控制方向

- `horizontal_error > 0`：目标在瞄准点右侧。
- `vertical_error > 0`：目标在瞄准点下方。

先用 `rov_axis_test` 确认艇体四轴正方向，再用极短、极小的指令观察目标是否向瞄准点收敛。右侧和左侧、上方和下方都必须复验。摄像头方向改变后重新标定。

确认完成后才填写 `image_yaw_sign`、`image_vertical_sign` 并设置：

```yaml
image_control_confirmed: true
```

### 11.4 抓取瞄准点和框面积阈值

默认瞄准点 `(0.50, 0.70)` 只是待标定起点。它应由摄像头和机械爪的实际相对安装决定，不是为了数值好看而固定为画面中心。

框面积比为：

```text
k = 框宽 × 框高 / (画面宽 × 画面高)
```

工具不会替人判断“爪子现在是否真能抓到”。程序先自动扫描和偏航对准，
稳定后停止自动运动，再由操作员在同一个 ROS 控制窗口中用 WASD 调整偏航、
深度和前后距离。工具把闭爪前那一刻的框位置、框面积、深度、姿态、人工
命令和截图记录下来。
本艇没有 DVL，所以工具不会伪造“目标距离多少米”；自主接近依靠
已标定的框面积和中心位置作为视觉反馈。

前置条件：

1. 第 9.1 节已经确认机械爪档案、输出口、方向和极限值；
2. QGC 可以观察并立即上锁；人工精调期间不能同时用 QGC 手柄驾驶；
3. BlueOS 已按第 7 节把 QGC 视频发到 `5600`、软件副流发到 `5700`，并把 ROS MAVLink 发到 `14551`；
4. 推进器危险区无人，安全员能够断电。

一键启动：

```bash
cd /home/persica/rov_competition_2026
./scripts/start_grasp_position_test.sh
```

该模式与自动接近测试共用同一套下潜、360°扫描、目标确认、漏检处理和
偏航对准逻辑。稳定对准后进入 `MANUAL_CALIBRATION`，四轴先回中，后续
运动全部来自该窗口的 `commissioning` 发布器。QGC 只观察和保留紧急上锁，
避免两个控制源互相覆盖。

现场循环：

1. 按住 `W/S` 前后、`A/D` 横移、`1/2` 转向、方向键上下调整抓取位置；松键立即回中。
2. 用 `+/-` 调整人工 power，默认 `0.10`，范围 `0.05～0.40`；`Space` 随时回中。
3. **在闭爪之前**按 `Enter` 或 `G`，保存框、遥测、最后运动命令和截图。
4. 按 `C` 发送闭爪；只有网关接受后才观察实物，真正抓住按 `Y`，未抓住按 `N`。
5. 按 `O` 单独开爪并继续调整。明显过远、过近、偏左/偏右或高度不对时，直接按 `B` 记录“不合格位置”，不用闭爪。
6. 当前样本处理完后，可继续记录；按 `R` 会先回到本轮搜索深度，再重新扫描 360°。
7. 按 `0` 正常回到启动深度并上锁；`Esc`、关闭窗口或 `Ctrl+C` 立即回中并走急停上锁路径。

未先保存位置时 `C` 会被拒绝；闭爪命令未被接受时 `Y/N` 也会被拒绝。
窗口失去焦点会立即回中并暂停，回到窗口后按 `Enter` 恢复。每次会话保存到：

```text
output/grasp_tests/YYYYMMDD_HHMMSS/
├── video_raw.mkv            # 与本次运动同步的原始视频
├── events.csv               # 状态、按键和实际四轴命令
├── detections.csv           # 每个新帧的识别框
├── grasp_samples.csv        # 闭爪前位置、网关服务响应和人工成败
├── screenshots/             # 与数值同帧的带框证据
├── recommended_grasp.yaml   # 待人工审核的建议
├── session.json             # 版本、配置、参数和退出原因
└── logs/
```

工具默认要求每类至少 5 个成功样本才生成数值建议；这只是防止
一两次偶然成功就改参数的最低门槛。真正现场标定建议每类至少 20 个
成功样本，再保留足够失败和不合格样本，覆盖不同角度、光照、姿态和水况。

`recommended_grasp.yaml` 的瞄准点来自成功样本中位数，每类面积阈值用
成功面积的 25% 分位作为保守起点。它**不会自动改写**
`autonomy.yaml`。先对照成功/失败截图审核；不同类别的瞄准点相差超过
画面 5% 时，工具会明确警告，不应盲目使用一个共同瞄准点。
人工复核后才把建议值复制到 `autonomy.yaml`，先做“只接近不闭爪”验证，
再做有安全员的低功率空抓和实抓。默认 `0.18` 不是验收结论。

机械爪尚未确认物理动作时，不得设置：

```yaml
grasp_thresholds_confirmed: true
```

### 11.5 最后开门

四轴方向、中位、急停、发布者崩溃和 MAVLink 断链全部通过后，才设置 `horizontal_motion_confirmed: true`。所有标定和故障测试完成后，才能人工打开：

```yaml
mission:
  allow_autonomous_mission: true
  allow_open_loop_horizontal_motion: true
```

启动被拒绝时，保存服务返回的完整缺项，不要删除检查逻辑。
