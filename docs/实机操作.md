# 实机操作：从只读到自主

## 0. 人员和机械条件

- ROV 必须在水中，不能让水下推进器长时间干转。
- 机械固定方式不能阻碍紧急断电，线缆不能进入桨叶。
- 一人负责电脑和命令；另一人只负责观察危险区、急停和断电。
- 每发一个命令前，操作员口述“预期哪个方向动、什么条件立即停”。
- QGC 保持遥测和人工上锁能力，但 ROS 测试时关闭手柄输出。

## 4. 打开点动所需的三道门

先停止终端 A 的网关并确认飞控上锁。编辑 `config/robot.yaml`：

```yaml
control:
  profile: "commissioning"
  allowed_flight_modes: ["MANUAL"]
  expected_frame_config: 2  # 这里只是格式示例，必须以实艇为准

safety:
  allow_live_actuation: true
  allow_ros_arming: true
  allow_gripper_actuation: false
```

重新启动网关：

```bash
ros2 launch rov_competition telemetry.launch.py \
  robot_config:="$PWD/config/robot.yaml" \
  enable_actuation:=true \
  enable_ros_arming:=true
```

网关会运行只读预检。任何关键项失败都不继续。

终端 B 开启运行时许可：

```bash
ros2 service call /rov/control/set_enabled std_srvs/srv/SetBool "{data: true}"
```

在 ROV 固定、危险区清空、飞控为 `MANUAL` 后，正常解锁：

```bash
ros2 service call /rov/control/set_armed rov_interfaces/srv/SetArmed \
  "{arm: true, confirmation: 'ARM ROV'}"
```

不要使用 `21196` 强制解锁。预解锁检查失败就解决原因。

## 6. 转向闭环

固定顺序：右转 `30° → 90° → 180° → 360°`。每一级通过方向、停止、上锁和跨零检查后才进下一级。

```bash
ros2 run rov_competition rov_turn_test \
  --direction right --angle 30 --value 0.05 \
  --config "$PWD/config/robot.yaml"
```

```bash
ros2 run rov_competition rov_turn_test \
  --direction right --angle 30 --value 0.05 \
  --config "$PWD/config/robot.yaml" \
  --execute --confirm "TURN ROV"
```

工具使用真实航向累计角度。航向跳变、实际方向相反、长期无进展、遥测过期、总超时或 `Ctrl+C` 都停止并上锁。

## 7. 视频前置分流和只读感知

比赛默认视频链路只有一次本机复制：

```text
树莓派 RTP/H.264 → 本机 UDP 5600 → QGC 5701
                                 └→ YOLO 5702
```

分流器使用 GStreamer `multiudpsink` 复制原始 RTP 包，不重新编码，也不把
QGC 窗口截出来。关闭 QGC 不应影响 YOLO；关闭 YOLO 也不应影响 QGC。
`5702` 的内部格式已经从旧链路的 MPEG-TS 改为 RTP/H.264，所以比赛启动
参数必须是 `gstreamer:=true`、`udp_mpegts:=false`。

### 7.1 推荐：一个终端一键启动

完成一次安装和编译后，平时只需要在一个终端运行：

```bash
cd /home/persica/rov_competition_2026
./scripts/start_video_test.sh
```

脚本会自动完成以下工作：

1. 启动 `5600 → 5701/5702` 原始 RTP 视频分流；
2. 启动 YOLO 识别；
3. 尝试打开 QGroundControl；
4. 安装了 `rqt_image_view` 时，尝试打开带框查看器。

QGC 只需提前设置一次：视频源选择 `UDP H.264`、端口填 `5701`，并打开
`Low Latency Mode`。带框查看器打开后选择基础话题
`/rov/annotated_image`，传输方式选择 `compressed`；不要直接订阅带
`/compressed` 后缀的传输子话题。

这个一键入口**不会启动飞控网关，不会解锁，也不会让推进器或机械爪动作**。
它只适合检查视频、延迟和检测框。回到启动终端按一次 `Ctrl+C`，视频分流
和 YOLO 会一起停止；QGC 可以继续保持打开。

YOLO 的 RTP 解码使用固定 50 ms 抖动缓冲。只读视频测试中若本地解码器
连续 3 秒没有得到完整帧，节点会重建 5702 解码管线并在恢复后继续发布，
不会影响始终独立的 QGC 5701 画面。自主任务已经启动时仍保持严格策略：
画面失效会触发安全中止，不会依靠自动重连继续盲走。

如果不想自动打开某个窗口，可以使用：

```bash
./scripts/start_video_test.sh --no-qgc
./scripts/start_video_test.sh --no-viewer
```

如果终端提示找不到 QGC，可手动打开；也可以指定 AppImage：

```bash
QGC_EXECUTABLE=/完整路径/QGroundControl.AppImage \
  ./scripts/start_video_test.sh
```

### 7.2 手动启动（只用于排错）

先确认真实控制、ROS 解锁和机械爪权限全部关闭。终端 A 启动分流器：

```bash
ros2 run rov_competition rov_stream_bridge \
  --source-port 5600 \
  --qgc-host 127.0.0.1 --qgc-port 5701 \
  --inference-host 127.0.0.1 --inference-port 5702 \
  --no-display
```

QGC 的视频源设置为 `UDP H.264`、端口 `5701`，并开启 `Low Latency Mode`。
QGC 不再监听 `5600`。设置方法见 [QGC Video 设置](https://docs.qgroundcontrol.com/master/en/qgc-user-guide/settings_view/video.html)。

终端 B 检查端口：

```bash
ss -lunp | grep -E ':(5600|5701|5702)\b'
```

应看到分流器接收 `5600`，QGC 接收 `5701`；启动 YOLO 后，自主节点接收
`5702`。QGC 和 YOLO 不允许使用同一个目标端口，也不能把输出发回本机
`5600`。

然后检查 GPU：

```bash
python - <<'PY'
import torch
print(torch.__version__)
print(torch.__file__)
print(torch.cuda.is_available())
print(torch.cuda.get_device_name(0) if torch.cuda.is_available() else "NO CUDA")
PY
```

实机环境必须显示 `.venv` 中的 CUDA 版 PyTorch、`CUDA=True` 和实际
GPU 名称。`autonomy.yaml` 显式配置 `device: "0"`，不允许在 CUDA 故障时
悄悄降级到 CPU。

终端 C 只启动识别，保持真实动作关闭：

```bash
export PYTHONNOUSERSITE=1
ros2 launch rov_competition competition.launch.py \
  robot_config:="$PWD/config/robot.yaml" \
  autonomy_config:="$PWD/ros2_ws/src/rov_competition/config/autonomy.yaml" \
  targets_config:="$PWD/ros2_ws/src/rov_competition/config/targets.yaml" \
  video_source:=5702 \
  gstreamer:=true \
  udp_mpegts:=false \
  display_window:=false \
  enable_actuation:=false \
  enable_ros_arming:=false
```

终端 D 查看结果：

```bash
ros2 topic hz /rov/detections
ros2 topic hz /rov/annotated_image/compressed
ros2 run rqt_image_view rqt_image_view
```

在 `rqt_image_view` 中选择 `/rov/annotated_image`，传输方式选择
`compressed`。用手机秒表同时
出现在真实场景、QGC 和带框画面里比较：YOLO 相对 QGC 的额外延迟目标不超过
`100 ms`，检测应接近相机实际帧率。先关闭 YOLO 确认 QGC 不断流，再重启
YOLO、关闭 QGC 确认检测仍继续。若两边同时花屏，排查水密缆、源编码或
5600 原始丢包；只有 YOLO 异常时再排查本机 5702 RTP 解码。

## 8. 键盘驾驶并拍摄数据集

这一步只用于人工驾驶拍摄新训练数据。它不启动 YOLO、不读取
权重、不控制机械爪，也不会“一启动就自动沉底”。下潜必须由操作员
按住向下方向键完成。日常操作请直接按
[键盘采集 README](键盘采集README.md) 执行；本节保留工程背景和参数解释。

### 8.1 一次配置

确认 `config/robot.yaml` 使用已经通过实艇点动的值：

```yaml
mavlink:
  connection_uri: "udpin:0.0.0.0:14551"

control:
  profile: "commissioning"
  allowed_flight_modes: ["ALT_HOLD"]
  command_limit: 0.80

safety:
  allow_live_actuation: true
  allow_ros_arming: true
  allow_gripper_actuation: false
```

复制数据集配置：

```bash
cp ros2_ws/src/rov_competition/config/dataset.example.yaml config/dataset.yaml
```

`config/dataset.yaml` 不再包含软件深度限制，只需核对键盘幅值：

```yaml
manual_control:
  initial_command: 0.20
  maximum_command: 0.80
```

深度只用于显示、日志和可选回收，不参与启动或驾驶门控。
姿态消息允许最多 `3.0 s` 的短时中断；飞控心跳、模式和控制状态仍按
原有更短阈值检查。

### 8.2 QGC 端口

一键脚本会把艇载的一份 MAVLink 分给 ROS 和 QGC，同时把一份
原始 RTP/H.264 分给 QGC 和录像器：

```text
MAVLink 14550 → ROS 14551 + QGC 14552
Video   5600  → QGC 5701 + Recorder 5702
```

QGC 只需设置一次：MAVLink UDP 监听 `14552`，视频选择
`UDP H.264: 5701` 并开启 Low Latency。QGC 必须保留人工上锁能力。

### 8.3 一键启动

安装、编译完成后，一个终端执行：

```bash
cd /home/persica/rov_competition_2026
./scripts/start_dataset_collection.sh
```

脚本依次检查环境和端口，启动 MAVProxy、飞控网关和原始视频分流，
然后开始 MKV 录像。它必须真正观察到录像文件增长，并确认
`ALT_HOLD`、真实深度、只读预检、ROV 已上锁和机械爪权限已关闭，
才显示最后现场确认词。

### 8.4 按键

| 按键 | 动作 |
|---|---|
| `W / S` | 前进 / 后退 |
| `A / D` | 左移 / 右移 |
| `1 / 2` | 左转 / 右转 |
| `↑ / ↓` | 上升 / 下潜 |
| `+ / -` | 每次增加 / 减少 `0.05` |
| `Space` | 四轴立即回中，ALT_HOLD 保持当前深度 |
| `0` | 正常停录像；深度可用则回收，否则直接上锁 |
| `Esc` / 关窗口 / `Ctrl+C` | 立即回中、锁存急停、上锁 |

默认幅值为 `0.20`，最高 `0.80`。只有按住才会运动；松开、
窗口失去焦点或按空格都会回中。可以按多个方向，每个轴保留设定的
指令强度；八推进器混控和最终输出饱和由 ArduSub 负责，每个轴仍受
网关 `0.80` 限幅。`0.80` 只是可调上限，必须从 `0.20` 逐级增加。

键盘采集不设置绝对或相对深度上限，也不会根据深度拦截向下指令。
深度可用时仍会显示和记录。

### 8.5 结束、故障和文件

正常结束必须按 `0`，顺序是：

```text
四轴回中 → 给录像器 EOS 并验证 MKV → 可选回启动深度 → 上锁
```

如果当前已比启动深度浅，工具不会为了追目标而重新下潜。若没有有效
深度，程序跳过自动回收并直接上锁。MAVLink、心跳、控制状态或模式
异常仍会急停上锁。

每次文件位于：

```text
output/datasets/YYYYMMDD_HHMMSS/
├── video_raw.mkv
├── events.csv
├── session.json
└── logs/
```

异常断电或封装失败时会保留 `video_raw.partial.mkv`，不会伪装成完整录像。
后续按每秒 5 帧抽图：

```bash
cd output/datasets/YYYYMMDD_HHMMSS
mkdir -p frames
ffmpeg -i video_raw.mkv -vf "fps=5" -q:v 2 frames/%06d.jpg
```

先人工删掉模糊、重复和无效帧，再标注。不要把连续视频每一帧都当成
独立样本，否则训练/验证集很容易泄漏几乎相同的画面。

### 8.6 有手柄时：只录像

已经能用 QGC 和手柄驾驶时，不要再启动键盘控制。完整步骤见
[手柄采集 README](手柄采集README.md)。日常只需运行：

```bash
cd /home/persica/rov_competition_2026
./scripts/start_dataset_recording.sh
```

脚本会自动尝试打开 QGC；首次仍须把 QGC 视频设为 `UDP H.264:5701`。
这个入口不读取 `robot.yaml`，不启动 MAVProxy、飞控网关、YOLO、
键盘驾驶或机械爪，也不占用 `14550/14551/14552`。QGC 和手柄的
原有 MAVLink 连接保持不变。

命令运行后会立即开始录制。采集完成后，先松开手柄并确认
ROV 停稳，再回到终端按 Enter。`Ctrl+C` 也会正常发送 EOS 并
封装 MKV，但它只停录像，不会替你停止、上锁或上浮 ROV。

输出目录为：

```text
output/datasets/YYYYMMDD_HHMMSS/
├── video_raw.mkv
├── session.json
└── logs/
```

`session.json` 会明确记录“本程序没有观察 QGC 手柄控制量”，不会把
未记录的飞控数据伪装成完整标注。

## 9. 切换到自主档案

只有单轴、转向、断链、视频和参数标定全部通过后：

1. 停止网关并确认上锁。
2. 将 `robot.yaml` 改为 `control.profile: "autonomy"`。
3. 将允许模式改为 `allowed_flight_modes: ["ALT_HOLD"]`。
4. 先独立确认机械爪的真实接线、供电、输出口和开合范围，再考虑 `allow_gripper_actuation: true`。目前机械爪尚未产生过可观察的物理动作，必须保持 `false`。
5. 按本文第 11 节完成 `autonomy.yaml` 的所有标定和记录。

保持第 7 节的分流器运行。另一个终端启动网关、感知和自主节点：

```bash
ros2 launch rov_competition competition.launch.py \
  robot_config:="$PWD/config/robot.yaml" \
  autonomy_config:="$PWD/ros2_ws/src/rov_competition/config/autonomy.yaml" \
  targets_config:="$PWD/ros2_ws/src/rov_competition/config/targets.yaml" \
  video_source:=5702 \
  gstreamer:=true \
  udp_mpegts:=false \
  display_window:=false \
  enable_actuation:=true \
  enable_ros_arming:=true
```

终端 B 观察：

```bash
ros2 topic echo /rov/mission/status
```

确认 QGC 已设为 `ALT_HOLD`，ROV 已完全浸没，依次调用运行时许可和正常解锁，然后开始任务：

```bash
ros2 service call /rov/control/set_enabled std_srvs/srv/SetBool "{data: true}"
```

```bash
ros2 service call /rov/control/set_armed rov_interfaces/srv/SetArmed \
  "{arm: true, confirmation: 'ARM ROV'}"
```

```bash
ros2 service call /rov/mission/start std_srvs/srv/Trigger "{}"
```

若返回失败，完整保存并阅读缺项列表。不要通过改代码删除门控。

人工中止：

```bash
ros2 service call /rov/mission/abort std_srvs/srv/Trigger "{}"
```

独立网关急停：

```bash
ros2 service call /rov/control/emergency_stop std_srvs/srv/Trigger "{}"
```

## 10. 必测故障

在固定和低功率条件下分别验证：

- 自主节点 `Ctrl+C`；
- 命令发布者进程崩溃；
- 摄像头断流；
- MAVLink 链路断开；
- 模式从 `ALT_HOLD` 变化；
- 深度或航向消息停止更新；
- 机械爪服务拒绝；
- 人工任务中止和网关急停。

每一种都必须保存终端完整日志、QGC 状态和录像。无法确认推进器停止并上锁时，不调试软件，先物理断电。

## 11. 自主参数标定

只从 `ros2_ws/src/rov_competition/config/autonomy.yaml` 最前面的 `field_tuning` 开始改。每次记录日期、电池、负载、水况、改前值、改后值、录像和结论；一次只改一类参数。

### 11.1 相对下潜

默认：

```yaml
descent_delta_m: 0.30
descent_tolerance_m: 0.05
```

ROV 实际下沉时，`/rov/telemetry.depth_m` 必须增加。先用已知水深检查零点和单位；数据反向或比例不对时，修正 `robot.yaml` 的深度换算，不要用状态机增益抵消传感器错误。

先确认能稳定进入容差，再调 `descent_gain`；不要一开始就提高 `descent_max_command`。

### 11.2 无 DVL 的前进距离

`0.40 m` 只能通过实测平均速度换算时间：

1. 固定使用 `advance_forward_command: 0.05`。
2. 在池边布置可测量的起点和终点。
3. 每次只运行短时间，至少重复 5 次。
4. 用人工测得的距离和时间计算速度。
5. 剔除碰撞、缆绳拉扯和明显流场干扰样例。
6. 用保守代表值填写 `advance_estimated_speed_mps`。

例如实测为 `0.20 m/s`，状态机会自动得到 `0.40 / 0.20 = 2.00 s`。电量、挂载、缆绳或水流变化后必须重测。

### 11.3 图像控制方向

- `horizontal_error > 0`：目标在瞄准点右侧。
- `vertical_error > 0`：目标在瞄准点下方。

先用 `rov_axis_test` 确认艇体四轴正方向，再用极短、极小的指令观察目标是否向瞄准点收敛。右侧和左侧、上方和下方都必须复验。摄像头方向改变后重新标定。

确认完成后才填写 `image_yaw_sign`、`image_vertical_sign` 并设置：

```yaml
image_control_confirmed: true
```

### 11.4 抓取瞄准点和框面积阈值

默认瞄准点 `(0.50, 0.70)` 只是待标定起点。它应由摄像头和机械爪的实际相对安装决定，不是为了数值好看而固定为画面中心。

框面积比为：

```text
k = 框宽 × 框高 / (画面宽 × 画面高)
```

每一类目标分开标定：在可以安全闭爪但尚未碰撞的距离，保存至少 20 张不同角度、光照和姿态的有效框，同时保存漏检、遮挡、贴屏和框跳变等失败样例。默认 `0.18` 不是验收结论。

机械爪尚未确认物理动作时，不得设置：

```yaml
grasp_thresholds_confirmed: true
```

### 11.5 最后开门

四轴方向、中位、急停、发布者崩溃和 MAVLink 断链全部通过后，才设置 `horizontal_motion_confirmed: true`。所有标定和故障测试完成后，才能人工打开：

```yaml
mission:
  allow_autonomous_mission: true
  allow_open_loop_horizontal_motion: true
```

启动被拒绝时，保存服务返回的完整缺项，不要删除检查逻辑。
